Controls
WASD / numeric keypad: eight-way grid movement with smooth slides.
Arrows: cardinal sword attacks, independent of movement direction.
Controller: left stick moves, right stick aims, right trigger attacks.
F1: pause and rebind controls. F2: pause for annotation.
Mouse input only operates menus. Rebindings are saved locally.

Playtest rules
Fi: 10 HP, 1.5 sword damage; three tiles ahead during a 0.12-second swing.
The active sword area follows Fi continuously and damages each target once.
After a damaging hit, Fi has ten gameplay frames of invincibility.
Regular enemies: 3 HP, 2 contact damage, 0.45-second steps, sensing radius 4.
On surviving a hit, an enemy recoils one legal tile over half a second;
blocked recoil staggers in place. Enemies show health above their artwork.
Boss: 50 HP, using an enlarged version of the supplied enemy drawing.
Within two tiles on the same row/column, it warns in red for two seconds,
then swipes a six-wide, two-deep rectangle for 4 damage. Cooldown: 5 seconds.

Meteor run
The original enemy section leads into a new 50-by-6-tile run, then the boss.
Meteors begin warning as Fi approaches the second enemy group.
Targets start at that group's spawn line and are chosen within the visible
area around Fi. Later warnings are separated by random 2–2.43-second waits.
A growing, rock-shaped shadow warns for 1.5 seconds before impact.
Drops randomly use 1-by-1, 2-by-2, or 3-by-3 tiles. The artwork,
shadow, hitbox, and crater obstruction all match that size.
Impact deals 3 damage to Fi. Craters block movement for two seconds.
Meteor footprints exclude live enemies (including reserved step targets)
and the boss. A drop is cancelled if an enemy enters its warned footprint.
Smaller meteors make quieter, higher sounds with shorter impact tails.

Motion panel
Tune Fi/enemy step duration, hold delay, attack cooldown, sensing range,
minimum/maximum meteor interval, and Fi/enemy horizontal/vertical offsets.
Changes are live for the current run; Restart restores the starting rules.
Offsets move artwork without changing grid occupancy or collision rules.
Disable EnableMotionPanel in Assets/Godlings/DemoRules.asset for production.

Artwork and audio
Fi and enemy sprites use supplied artwork; no generative artwork was made.
Meteor/crater use Untitled_Artwork 7.png. Only the bottom soil contact rim
blends toward pale green (#BBD6AB); raised soil and rock keep their colors.
The shadow is traced from the visible rock silhouette, excluding the soil.
The original drawing is preserved unchanged in Art/Originals.
Fi uses a temporary synthetic fox yelp, regular enemies short burps,
and the boss a louder, deeper, 1.4-second burp. Meteors whoosh and impact.
Final animations, scenery tiles and title screen remain artist-provided.
Faith mechanics and additional story content have not been invented.

URP MIGRATION — 17 October 2026
Rendering now uses Universal Render Pipeline 17.6.0 with its 2D renderer
(Unity 6000.6.6f1). Gamma color space, artwork, projection, palette, sorting,
and gameplay are preserved. No lighting or post-processing is added.
Assets/Godlings/Rendering contains the pipeline, 2D renderer, and explicit
unlit materials. SpriteUnlit uses Unity's URP sprite shader; VertexColorUnlit
is a small URP shader for the existing colored floor and warning meshes.
Graphics Settings and every Quality level reference the same URP asset.
DemoBuilder.Prepare calls RenderingSetup.EnsureConfigured, then serializes
both material references into the scene so builds retain their shaders.
Keep all rendering assets and their .meta files together when pulling changes.
The optional screenshot smoke check uses URP's SubmitRenderRequest API.
In-app purchasing was unused: its deprecated package was removed rather than
adding purchase functionality. Monetization remains undecided by Dominik.

Windows x64 builds require Windows Build Support (Mono) for Unity 6000.6.6f1.
Install it through Unity Hub, then use Godlings > Build Windows demo.
Batch command: Unity -batchmode -quit -projectPath PROJECT -buildTarget Win64
-executeMethod Godlings.Editor.DemoBuilder.BuildWindows -logFile BUILD_LOG
Output: Builds/Windows/Godlings Demo.exe, with its data, runtime, and instructions.
Distribute the whole build folder, not only its .exe. Test on an actual Windows PC.
Windows IL2CPP builds require a Windows editor plus the native C++ toolchain.
